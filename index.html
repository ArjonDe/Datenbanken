Datenmodellierung – Theorie

Von der Idee zur fertigen Tabelle in 5 Schritten, nach dem Skript (Kap. 8–10).

Schritt 1: Das ER-Modell ist der Bauplan

Bevor man Tabellen anlegt, zeichnet man einen Plan der Daten. Ein Entitätstyp (Rechteck) ist eine Sorte von „Dingen“, z. B. Angestellter oder Projekt. Eine Beziehung (Raute) sagt, wie zwei Sorten zusammenhängen: Angestellter leitet Projekt. Das ist die Chen-Notation. Jeder Entitätstyp wird später zu einer Tabelle, jede Entität zu einer Zeile.

So liest du die Zahlen (Kardinalitäten): Sie stehen am jeweils gegenüberliegenden Entitätstyp. Das N neben „Projekt“ heißt: Ein Angestellter kann mehrere Projekte leiten. Die 1 neben „Angestellter“ heißt: Ein Projekt wird von genau einem Angestellten geleitet.

SymbolBedeutungMerkhilfe
1genau einer„muss“
Chöchstens einer„kann“ (choice)
M / Nmehrere, mindestens einer„muss“
CMmehrere oder keiner„kann“

Schritt 2: 1:N wird zu zwei Tabellen mit einem Fremdschlüssel

Ein Fremdschlüssel ist eine Spalte, die nur Werte enthält, die in einer anderen Tabelle als Primärschlüssel vorkommen. Er ist wie ein Verweis. Merksatz: Der Fremdschlüssel kommt auf die N-Seite. Ein Angestellter hat nur eine Abteilung, dafür reicht eine Spalte. Umgekehrt bräuchte eine Abteilung beliebig viele Spalten für ihre Angestellten.

Die Pfeile zeigen, wer auf wen verweist. Bei „muss“ (1) schreibt man NOT NULL an den Fremdschlüssel, bei „kann“ (C) darf er leer (NULL) sein.

Schritt 3: M:N braucht eine dritte Tabelle

Eine Spalte kann keine Liste speichern. Deshalb löst man M:N mit einer Beziehungstabelle auf. Jede Zeile dort ist ein Paar, das zusammengehört. Hier arbeitet Anna an „Web“ und „App“, Bert an „Web“. Beide Fremdschlüssel zusammen bilden den Primärschlüssel (unterstrichen). Die Tabelle darf weitere Spalten haben, z. B. stunden.

Namenskonvention: Entitätstypen im Singular, Tabellen im Plural. Eine Tabelle mit Fremdschlüssel kann erst angelegt werden, wenn die referenzierte Tabelle existiert.

Schritt 5: Normalisierung räumt die Tabellen auf

Warum? Steht zu viel Information in einem Datensatz, drohen Anomalien. Beispiel aus dem Skript: Die Tabelle alben(reihe, band, titel, verlag, jahr) speichert den Verlag bei jedem Album. Einfügeanomalie: Ein Tippfehler legt „Asterix“ plötzlich bei einem zweiten Verlag an. Änderungsanomalie: Ein Update ändert nur ein Album, die anderen behalten den alten Verlag. Löschanomalie: Wird das einzige Album von „Tim und Struppi“ gelöscht, ist auch der Verlag der Reihe weg. Lösung: eine eigene Tabelle reihen mit dem Verlag.

NFBedingungBeispiel und Lösung
1NFNur einfache Werte, keine Tabelle in einer Spaltekunden(…, AuftragsNr) mit mehreren Aufträgen → Fremdschlüssel in auftraege
2NFJedes Nichtschlüsselattribut hängt vom ganzen Primärschlüssel abPositionen(ArtikelNr, AuftragsNr, Menge, Preis): Der Preis hängt nur von ArtikelNr → Preis nach Artikel
3NFKeine transitiven AbhängigkeitenArtikel(…, LagerNr, Lagerort): Lagerort hängt über LagerNr am Artikel → Tabelle Lager
4NFNichts Berechenbares speichernBruttopreis = Netto + Steuer → Spalte streichen

Daumenregeln: 1NF nur verletzt, wenn bei 1:N der Fremdschlüssel auf der 1-Seite steht. 2NF nur bei einem Primärschlüssel aus mehreren Spalten. 3NF nur, wenn ein Fremdschlüssel fehlt, der da sein sollte. 4NF nur bei berechenbaren Attributen.
